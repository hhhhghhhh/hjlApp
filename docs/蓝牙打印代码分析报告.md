# hjlApp 蓝牙打印子系统 · 代码分析报告（维护/排障定位用）

> 适用范围：hjlApp（uni-app v3，Android PDA）蓝牙标签打印模块
> 目标：让接手维护的人能快速定位"打印相关代码在哪、改什么、坑在哪"
> 代码基准：截至 2026-08-28 的 `utils/` + `pages/print/` + `components/mes/print/`

---

## 0. 一句话架构

**连接层（printerConnection）** 只负责连蓝牙 + 收发字节，与打印机型号/指令集无关；
**管理器（printerManager）** 是单例入口，按"指令集协议"选适配器、记忆每台打印机的协议、自动回连；
**适配器（adapters/*）** 把统一的"中性模板"翻译成各品牌指令（ZPL / LPAPI / IB-PTM7330 位图）；
**中性模板（labTemplate + zplTemplate + lpapiTemplate）** 是各打印机共享的与机型无关的标签描述（单位 mm），
**页面（printSetting / labelImport / labelTemplate / keySnPrint…）** 负责 UI 与触发。

## 1. 分层架构与数据流

```
                  [业务页面 / 模板编辑页 / SN 打印页]
                          │  import printer from '@/utils/printerManager.js'
                          ▼
                  ┌───────────────────────┐
                  │   printerManager.js     │  单例、对外统一 API、按 MAC 记忆协议、自动回连
                  └───────────┬───────────┘
                              │  ensureAdapter(proto)
                              ▼
                  ┌───────────────────────┐
                  │  printerAdapter.js     │  PrinterAdapter 基类 + 工厂 FACTORY（动态 import）
                  └───────────┬───────────┘
              ┌───────────────┼───────────────────────┐
              ▼               ▼                        ▼
     ┌────────────┐  ┌────────────────┐     ┌──────────────────┐
     │zebraAdapter│  │ibptm7330Adapter│     │  lpapiAdapter     │
     │  (ZPL)     │  │ (BLE 位图/TPCL/ │     │ (dothan-lpapi-ble)│
     │            │  │  ESC/POS 后备)   │     │  Canvas+uni BLE   │
     └─────┬──────┘  └────────┬────────┘     └────────┬─────────┘
           │ SPP 字节          │ BLE GATT 字节          │ 自管 BLE（SDK）
           ▼                   ▼                        │  + 隐藏 canvas 绘制
   ┌──────────────────────────────────┐               │
   │      printerConnection.js         │◄──────────────┘ (LPAPI 不走此层)
   │  SPP(RFCOMM) + BLE(GATT) 收发     │
   │  normalizeAddress / getPairedDevices│
   └──────────────────────────────────┘

   中性模板生成链（与打印机无关）：
   CSPrintService .Lab 解析 → 二维码
        → decodePayload (labTemplate.js)         // 离线码 gzip+base64 / 回连码 JSON
        → toZplTemplate() → convertDetail()       // CodeSoft 全量 detail → 中性模板
        → builtinTemplates()                       // 三张内置默认模板（同路径生成）
   打印时：
   printerManager.printTemplate(tpl, data)
        → adapter.printTemplate(tpl, data)
        → ZebraAdapter: buildZpl(tpl,data,fontOpts)        // mm → 点(ZPL)
        → LpapiAdapter:  renderTemplateToLpapi(...)         // mm 直接下发 draw 调用
```

**关键约定（排障必读）**
- 中性模板所有尺寸以 **mm** 存储，**模板本身不记录 dpi**。dpi 在打印时按"连接打印机的真实分辨率"折算（ZPL 折算成点；LPAPI 直接以 mm 下发由 SDK 按打印机 dpi 栅格化）。
- 连线即"指令集（proto）"，与 MAC 绑定记忆（`printer_protocol_<MAC>`）。

## 3. 各层详解

### 3.1 连接层 `printerConnection.js`
- **两种连接**：`connectSPP`（经典蓝牙 RFCOMM，UUID `00001101`）走 `createRfcommSocket` → 失败逐个试"安全/非安全通道"（Android 12+ 安全通道常被拒，见 L189-193 注释）；`connectBLE`（uni BLE API，GATT）用于 LPAPI/IB-PTM 系。
- **重要**：LPAPI 协议**不走此层**——`printerManager` 在 `connect/disconnect/isConnected` 里对 `PROTOCOLS.LPAPI` 直接调 `adapter.xxx`，不走 `conn`。改 SPP 行为不影响 LPAPI。
- `normalizeAddress(raw)`（L110-115）：机身条码是 12 位十六进制无分隔符，统一规整成 `AA:BB:CC:DD:EE:FF`。MAC 解析失败的报错常源于此。
- `sendBytes` 分流：BLE 走 `sendBytesBLE` 自动分包（按 MTU，默认 200-3）；SPP 走 `sendRaw(bytesToString,'ISO-8859-1')`（L462-468）。
- **Android 权限**：`requestPermissions`（L64-83）Android 12+ 请求 `BLUETOOTH_CONNECT/SCAN`。没授权时 `getPairedDevices` 抛 SecurityException → 设置页列表空白（见 printSetting.refresh 注释 L354-356）。

### 3.2 管理器 `printerManager.js`
- 单例 + 懒加载适配器：`ensureAdapter(proto)` → `createAdapter(proto)`（动态 import）。
- **按打印机记忆协议**：`printer_protocol_<MAC>`（L20-28）。`connect()` 优先用该 MAC 记忆 → 否则用全局上次选择；连成功后写回（L74-86）。`clearPrinter()` 清全局键但**保留**各 MAC 记忆（只删 `PROTOCOL_KEY`）。
- **自动回连** `_ensureConnected()`（L196-214）：业务页打印前若未连，用 `conn.loadPrinter()` 的默认机 + 该机记忆协议自动连；连完再确认 `isConnected()`，未连上**明确报错**（避免"以为打了其实没打"的静默失败，见 L207-213 注释）。
- **协议层方法守卫**：`printTestPdf/Tpcl/Esc/Lpapi` 都是先 `await _ensureConnected()` 再 `adapter.xxx`，若适配器未实现就抛"当前协议不支持"清晰错误（L153-175），不会 `undefined is not a function` 崩溃。
- **dpi 来源** `getPrinterDpi()`（L275-280）：取 `adapter.printerDpi` 或 `adapter.dpi`，未连接为 `null`。Zebra 连后查 `device.dpi`（默认 203），LPAPI 取 `getPrinterInfo().printerDPI`（实测 300），IB-PTM7330 固定 300。
- **LPAPI 偏移微调**（全局，一次设置所有 LPAPI 打印入口通用）：`getOffsetDelta/setOffsetDelta`（水平）、`getOffsetDeltaY/setOffsetDeltaY`（垂直）。这是叠加在打印机 `printerAlignment` 自动基线之上的 **delta**（正=右移/下移）。`getPrinterAlignment()` 返回 0/2/4（右/中/左），未连 LPAPI 返回 null。

### 3.3 适配器基类与工厂 `printerAdapter.js`
- `PROTOCOLS`：`zebra / ibptm7330 / lpapi / esc / tpcl / pdf`。**设置页只展示 `LPAPI` 与 `ZPL` 两个中性选项**（`PROTOCOL_OPTIONS` L23-26）。
- `detectProtocolByName(name)`（L45-51）：按蓝牙名正则预选（Zebra→ZPL；IB-PTM/PTM7330/DT7330/DOTHAN→LPAPI）。**仅在"该 MAC 无记忆"时首次自动预选**，一旦记忆优先。
- `PrinterAdapter` 基类：连接默认复用 `conn.connect`（SPP）；`supportsElement` 列出各协议支持的元素类型。
- **工厂 FACTORY**（L123-131）：`zebra→zebraAdapter`、`lpapi→lpapiAdapter`、`esc/tpcl/pdf/ibptm7330→ibptm7330Adapter`。新增指令集：实现 `PrinterAdapter` 子类 + 在 FACTORY 加一行。

### 3.4 Zebra 适配器 `zebraAdapter.js`
- `connect()`（L24-35）：`super.connect` → `~HS` 验证（`_verifyConnection`）→ `_queryDpi()`（ZR668=203，ZT/ZD 可能 300/600，查 `device.dpi`）→ `checkTtfFont()`（**必须 await**，否则 `hasTtfFont()` 仍为 false 导致中文误走位图，见 L30-33 注释）。
- **CJK 策略**（与历史 GB18030 不同）：优先 `^A@ E:HANS.TTF` 原生渲染；无 TTF 时降级 `^GFA` 位图（`zplTemplate` 决定）。`getCjkFontPath()` 返回 `E:HANS.TTF` 系列，不再依赖 `E:GB18030.FNT`。
- `applyMedia`（L115-118）→ `buildApplyMediaCommand`：连续纸 `^MNN^LL`；间隙/黑标 `^MNY/^MNM^LL + ~JC` 校准。

### 3.5 IB-PTM7330 适配器 `ibptm7330Adapter.js`（后备，不在设置页出现）
- 连接方式 `ble`（GATT，BLE 常量见 L14-18，Service `FF00`/Write `FF02`）。
- 三类测试：`printTestPdf`（1F 2A 位图，最可靠）、`printTestTpcl`（TSPL）、`printTestEsc`（ESC/POS）。**无内置中文字库**，所有内容经 Android Canvas 渲染成位图后按行下发。
- **位图铁律**：`dpi` 固定 `300`（L50），`setLabelSize/printTextLines` 均忽略外部 dpi（绝不收模板的 203），见 L54-60、L147-152 注释。
- 位图读取有"快通道"`readBitmapPixelsFast`（copyPixelsToBuffer→Base64→JS 二值化，毫秒级）与"慢通道"`readBitmapPixelsSlow`（逐像素 getPixel，仅兜底）两条路径（L287-387）。

### 3.6 LPAPI 适配器 `lpapiAdapter.js`（当前主力机型 PTM230X）
- **连接** `connect()`（L225-276）：`openAdapter({force:true})` 预检蓝牙 → 带重试（最多 3 次，失败重置适配器）`openPrinter({name,deviceId,tryTimes})` → `isPrinterOpened()` 二次确认。专治 `createBLEConnection:fail no device errCode 10002` 的静默失败（见 L221-224 注释）。
- **介质信息** `_refreshMediaInfo()`（L281-315）：连后读 `getPrinterInfo()` 取 `printerDPI / printerWidth(点) / softwareFlags`。对齐方式从 `softwareFlags` 派生 `(sf & 0x600) >> 8`（L307），**不是**直接读 `printerAlignment` 字段（SDK 不返回）。本机 PTM230X：`printerWidth=576点@300dpi≈48.8mm`、`softwareFlags=0xd0 → 0`（右对齐）。
- **偏移核心** `computeOffsetX()`（L129-155）：
  - 基准 = **打印头可打印宽度** `printableMm = printerWidth/dpi*25.4`（**不是介质宽 paperWidth**，踩过 3 次坑，见 L126-128 注释）。
  - 右对齐(0)：`off = printableMm - labelW`；居中(2)：`/2`；左对齐(4)：0。
  - delta：优先 `tpl.page.offsetXMm`（个别模板特调），否则全局 `lpapi_offset_delta`。
  - **PTM230X 数值复核**：`(48.8 - 20)/... = 28.77` 与日志吻合。
- **startJob 后必须同步 canvas 的 :style**：`_startJob()`（L341-373）调 `ensureDrawContext()` → `lpapi.startJob(...)` → 用返回 `job.canvas` 像素 `emitCanvasSize(w,h)` → 页面 120ms 后绘制。**绝不直接改 canvas 节点的 width/height 位图**（SDK 已在 startJob 内把节点位图设成任务像素，再 `node.width=w` 会清空 SDK 位图→出纸空白，见 L339-340 注释）。
- **二值化铁律**：`startJob` 必传 `colorMode:2`（黑/白二值化），`buildCommitOpts` 也显式 `colorMode:2 / threshold:150`，否则 canvas 灰阶原样下发→发虚（"完全不清晰"），见 L101-106、L353-357。
- `printTemplate`（L499-535）：铺满打印头宽度 `jobW=max(printableMm,labelW)` → `renderTemplateToLpapi(lpapi,tpl,data,dpi,{offsetXMm,offsetYMm})` → `commitJob({mediaType,printCopies})`。`commitJob` 返回的 `ret` 含循环引用（`UniContext`），**严禁 `JSON.stringify`**（L171-179）。
- `applyMedia/calibrate` 对 LPAPI 都是"打印一张当前尺寸的校准标签"，让传感器量间隙（L444-455）。`_printCalibrationLabel`（L460-493）画出 3 个候选框 + 满宽刻度尺供肉眼读偏移。

### 3.7 事件总线 / 插件加载 `lpapi-uniplugin.js`
- 静态 `import { LPAPIFactory } from '../uni_modules/dothan-lpapi-ble/js_sdk'`（L25）——**uni_modules JS 插件，标准基座即可，无需自定义基座**。
- 每个打印页一个唯一 `canvas-id`，各自持一份绘制上下文 `contexts[canvasId]`（L82），`currentCanvasId` 记录当前页。早期"全局共用一份"导致 navigateTo 后 commitJob 取到旧页空 canvas→出纸空白（L77-81 注释）。
- `initDrawContext(canvasId)` 在页面 `onLoad` 调；`setActiveCanvas(canvasId)` 在 `onShow` 调（保证 navigateBack 后"当前画布"切回本页）。
- **尺寸事件总线**：`emitCanvasSize(w,h)` / `onCanvasSize(fn)` 解耦"适配器（utils 层）"与"页面（pages 层）"——适配器无法直接改 Vue 响应式 data，故用事件通知页面把 `lpapiCanvasW/H` 改成任务像素。

### 3.8 中性模板生成 `labTemplate.js`
- `decodePayload(raw)`（L139-167）：`{` 开头→JSON（回连码 `{ws,cmd:'ParseLab',labelFile,view}`）；否则→`pako.ungzip(base64ToBytes(raw))` 解出 JSON（离线码 gzip+base64）。**pako 3.x 必须 `import * as pako`**（命名空间导入），`import pako from 'pako'` 在 ESM 下为 undefined → `pako.ungzip` 报错（L13-15 注释）。
- `toZplTemplate(input, rawInput)`（L373-388）：兼容 `detail`（全量，优先）与 `pdaTemplate`（精简）两种 CSPrintService 输出；**优先 detail**（信息最全）。
- `convertElement`（L250-361）：**横线(width>0 && height<=0)必须映射成中性 `line`**，否则 LPAPI 渲染器按 box 处理会 `h<=0` 跳过→横线丢失（ZPL 的 `^GB w,0` 恰好能画掩盖了不一致，见 L340-343 注释）。竖线(height>0 && width<=0)降级为极窄 `box`。
- `convertDetail`（L532-607）：**剥离页边距/排版字段**（`pageWidthMm/marginLeftMm/marginTopMm/columns/rows/portrait/stockName…`），否则实际打印与设计稿偏移。
  - `detail.LabObject` 易错映射：`lineWidthMm`（**非** pdaTemplate 的 `thicknessMm`）、`printable===false` 跳过、`moduleXMm`（模块尺寸）、QR 放大倍率按 `moduleXMm×203/25.4` 折算。
  - **`normalizeDetailObject` 对文本必写 `out.height = obj.heightMm`**（L487）：否则渲染层读 `el.height` 回落 3mm 兜底，字号偏小（踩过的坑）。
- 内置三张默认模板 `builtinTemplates()`（L679-694）：走**真实 CodeSoft 导入路径** `convertDetail(buildBuiltinDetail(...))`，保证与导入模板 100% 同构、不漂移。源 `BUILTIN_ITEM_LOT_SN_DETAIL`（L616-662）：20×15mm，QR center(5,5)/5.33²/module0.25/eccQ，Text1 itemLotSn TL(10,1) 8.5×1.61mm 宋体4.5pt，Text3 itemName TL(0.47,10) 19×1.82mm 宋体5pt。

### 3.9 ZPL 生成 `zplTemplate.js`
- `buildZpl(tpl,data,opts)`（L374-409）：`opts.dpi` 优先（适配器传真实 dpi）→ 否则模板 dpi → 兜底 203。`^CI28`（UTF-8）→ `media.zpl` → `^PW/^LL` → 逐元素 `renderElement`。
- **CJK 渲染优先级**（renderElement，L268-310）：① 有 TTF → `^A@` 原生；② 无 TTF 但 `isBitmapSupported` → `^GFA` 位图（`renderTextToGfa`）；③ 兜底 `^A@ E:HANS.TTF`。
- `buildApplyMediaCommand`（L416-424）：连续纸 `^MNN^LL{dots}^JUS`；间隙/黑标 `^XA{media}^LL{dots}^JUS^XZ\n~JC`。
- **模板持久化**：`loadTemplates()`（L534-551）**纯合并**——首次写入内置、启动不覆盖用户已有；`overwriteBuiltinTemplates()`（L555-564）按 id 覆盖三张内置、保留自建，**仅由模板页「覆盖默认模板」按钮触发**（之前"启动自动覆盖"会冲掉手动保存，已反转）。
- `migrateTemplate`（L502-532）：旧模板以"点+page.dpi"存储，加载时一次性折算成 mm 并删 `page.dpi`。

### 3.10 LPAPI 渲染 `lpapiTemplate.js`（含二维码自适应）
- `renderTemplateToLpapi(lpapi,tpl,data,_printerDpi,opts)`（L112）：中性 mm 坐标直接下发，不做 dpi 折算（`_printerDpi` 仅兼容保留）。
- `renderText`（L162-231）：单行 `frameH>0` → `fontHmm=frameH`、`autoShrink=false`、`height:0 + autoHeight:true`（**框高即字号**）；多行不收缩按内容撑高；**传 `minFontHeight:0.1`** 压低 SDK 默认 2mm 字号地板（SDK 源码 `FONT_SIZE_MIN_DEFAULT=2`，否则"往小调不行"，见 L219 注释）。
- `renderQrcode`（L233-257）**二维码自适应**（用户关注点）：
  - `frameMm = el.width`（内置 5.33mm）。
  - `minMm = qrMinScannableMm(byteLen, ecc, dpi)`：按字节数查 `QR_CAP_BYTES` 取最小版本 v → 模块数 `(17+4v)+8`（+8 静默区）→ × `(2.15*25.4/dpi)`（2.15 点/模块 安全密度）。
  - 若 `minMm > frameMm` → 放大到 `minMm` 并打 warn（如 37 字节 keySn@Q → v4 → 7.46mm）。
  - **这是"尽力放大防过密"，不是绝对保证**（详见第 5 节 QR 自适应边界）。
- 越界检测（L127-135）：元素超出标签范围进 `report.offLabel`，仅告警不缩放——放大后若标签比 QR 小会被物理裁切。

### 3.11 CJK 位图 `cjkBitmap.js`
- `renderTextToGfa(text,opts)`（L244）：Android `Bitmap+Canvas+Paint` 反射渲染 → 逐像素读 `getPixel` → 判 alpha>127 且 R<128 为黑 → 输出 `^GFA` 十六进制。
- 超采样 `superSample`（1-4）：在 ss 倍分辨率画再 `createScaledBitmap` 降采样，小字号更清晰但慢 ss² 倍。全局质量 `getBitmapQuality()`（`speed`=ss1 / `clear`=ss2）。
- **反射铁律**（L78-129 注释）：枚举实例用**直接字段访问** `C.BitmapConfig.ARGB_8888`，不能用 `Cls.valueOf('X')`（被 `Function.prototype.valueOf` 拦截返回 Class 本身）；`plus.android.getAttribute` 也拿不到静态字段。

### 3.12 兼容 shim `zebraPrinter.js`
- 旧 `import printer from '@/utils/zebraPrinter.js'` 全部透明转发到 `printerManager`/`printerConnection`，共享同一连接状态。**改打印逻辑只改新架构即可**。

## 4. 三条打印路径对照（排障时按协议分）

| 步骤 | Zebra (ZPL, SPP) | LPAPI (PTM230X, 自管 BLE) | IB-PTM7330 (BLE 位图, 后备) |
|---|---|---|---|
| 连接 | `conn.connectSPP` | `lpapi.openAdapter/openPrinter` | `conn.connectBLE` |
| 尺寸来源 | 模板 mm + 查 `device.dpi` 折算点 | SDK 按 `printerDPI` 栅格化，mm 直发 | 固定 300dpi 位图 |
| 中文 | `^A@ HANS.TTF` / `^GFA` | Canvas 原生 drawText | Canvas 位图 |
| 校准 | `^LL`(连续) / `~JC`(间隙) | 打印一张校准标签 | 无（位图按行，无需） |
| 偏移 | 无（ZPL 坐标即落点） | `computeOffsetX`（打印头宽基准 + delta） | 无需 |
| 出纸空白主因 | 编码/字体 | canvas `:style` 未同步 / 直接改 `node.width` | 位图分辨率错 |

## 5. 高频坑 · 症状→根因→定位表

| 症状 | 根因 | 定位文件:行 |
|---|---|---|
| **LPAPI 出纸空白** | startJob 后只同步 `:style`，却额外 `node.width=w` 清空 SDK 位图 | `lpapiAdapter._startJob` L339-340、`_resizeCanvas` L378 |
| **LPAPI 出纸空白（多页无反应）** | 页面缺唯一隐藏 canvas，或 `initDrawContext` 失败、`setActiveCanvas` 未调 | `lpapi-uniplugin.js` L77-82、各打印页 `onLoad/onShow` |
| **打印偏左/印到标签外** | 偏移基准用了"介质宽 paperWidth"而非"打印头宽 printerWidth" | `lpapiAdapter.computeOffsetX` L126-128、L129-155 |
| **PTM230X 整体偏右** | `softwareFlags=0xd0 → 右对齐(0)`，`off=printableMm-labelW=28.77` 正确；误以为 bug | `lpapiAdapter._refreshMediaInfo` L305-311 |
| **走纸比标签长/跨张** | ① 间隙/黑标纸换纸未 `~JC` 校准，传感器仍按旧长度；② 连续纸 `^LL` 未生效；③ dpi 填错放大（203 当 300→长 1.48 倍） | `zplTemplate.buildApplyMediaCommand` L416-424；`buildZpl` L391 |
| **中文乱码/空白** | Zebra 未检测到 `HANS.TTF`，误走位图或 `^A@` 无字体 | `zebraAdapter.checkTtfFont` L222-258、`zplTemplate.renderElement` L268-310 |
| **二维码扫不出** | 长 SN 被压到 ~1.5 点/模块（过密）；自适应只放大到 2.15 点/模块经验值，非物理下限；标签比放大后 QR 小→被裁 | `lpapiTemplate.renderQrcode` L233-257、`qrMinScannableMm` L71-76 |
| **字"往大调行、往小调不行"** | SDK `autoShrink` 只缩不放 + 2mm 地板。现改 `fontHmm=frameH` 关 autoShrink + 传 `minFontHeight:0.1` | `lpapiTemplate.renderText` L162-231 |
| **文本 topLeft 锚点改框高无效** | `showFrame(el)` 曾含 text 导致框高输入隐藏；已改 `showFrame` 不含 text | `labelTemplate.vue`（编辑器面板） |
| **模板导入后尺寸偏移** | detail 未剥离 `marginLeftMm/pageWidthMm` 等排版字段 | `labTemplate.convertDetail` L521-531 |
| **横线在 LPAPI 丢失** | 横线被映射成 `box`（h<=0 跳过），应映射成 `line` | `labTemplate.convertElement` L340-357 |
| **离线码导入失败/截断** | 输入框 `maxlength` 默认 140，长离线码第 141 字被丢；用实体扫码头或改回连码 | `labelImport.vue` textarea `maxlength="-1"` L15 |
| **LPAPI 连不上 errCode 10002** | 蓝牙未开/未授权/打印机未进可连接模式；早期"假连接"出纸空白 | `lpapiAdapter.connect` L225-276 |
| **文本字号偏低（如 3mm 兜底）** | 转换只写 `heightMm` 没写 `el.height`，渲染回落 3mm | `labTemplate.normalizeDetailObject` L485-487 |
| **commitJob 序列化崩溃** | `ret` 含 `UniContext` 循环引用，不能 `JSON.stringify` | `lpapiAdapter.safeRet` L171-179 |

## 8. 已知边界 / TODO（未做）
- 下划线/删除线/颜色：SDK 无入口。
- ZPL 链路深主题/图片/标签矩阵未做。
- `qrMinScannableMm` 的 2.15 点/模块是**经验值**，非物理下限；对比度差/点增益大/扫描头弱时仍可能扫不出。
- 标签实际物理尺寸 < 放大后 QR 时，QR 被裁切且只告警不缩（见 3.10）。
- 真机观感需实测核对（A5 字号、横线、偏移）。
