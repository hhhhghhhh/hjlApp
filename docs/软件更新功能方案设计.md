# 应用更新方案 —— 按钮点击下载安装固定 APK

> **需求变更说明**（2026-09-03）：原「版本检测 + 版本比较」方案作废。
> 新需求：**「我的」页放一个更新按钮 → 调后端接口 → 下载 `snApp.apk` → 安装**。
> 不做版本比较；APK 文件放在**部署后 `iwms.jar` 的同级目录**，换版本只需替换该文件，**不用重新打包部署**。

> 本文为方案设计，未修改任何代码。

## 三、后端实现

### 3.1 新增 Controller

**文件**：`mes-core-pda/src/main/java/cc/admin/modules/pda/controller/PdaAppUpdateController.java`

```java
package cc.admin.modules.pda.controller;

import io.swagger.annotations.Api;
import io.swagger.annotations.ApiOperation;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.boot.system.ApplicationHome;
import org.springframework.util.StringUtils;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import java.io.*;
import java.net.URLEncoder;
import java.nio.charset.StandardCharsets;

@Slf4j
@Api(tags = "pda应用更新")
@RestController
@RequestMapping("/api/pda/app")
public class PdaAppUpdateController {

    /** 固定文件名：运维直接替换这个文件即可换版本 */
    private static final String APK_NAME = "snApp.apk";

    /**
     * APK 所在目录。留空 = jar 同目录（推荐）；
     * 若部署方式特殊导致定位不准，可在 yml 里显式配置。
     */
    @Value("${cc.admin.path.apk:}")
    private String apkDirConfig;

    @ApiOperation(value = "下载 snApp.apk", notes = "读取 jar 同目录下的 snApp.apk 并返回文件流")
    @GetMapping(value = "/downloadSnApp")
    public void downloadSnApp(HttpServletRequest request, HttpServletResponse response) {
        File file = resolveApkFile();
        if (file == null || !file.exists()) {
            log.warn("[appUpdate] APK 不存在: {}", file == null ? "null" : file.getAbsolutePath());
            writeJson(response, HttpServletResponse.SC_NOT_FOUND, "服务器上未找到 " + APK_NAME);
            return;
        }

        long len = file.length();
        log.info("[appUpdate] 下载 {}，大小 {} 字节，路径 {}", APK_NAME, len, file.getAbsolutePath());

        response.reset();
        response.setContentType("application/vnd.android.package-archive");
        response.setCharacterEncoding("UTF-8");
        response.setContentLengthLong(len);
        response.setHeader("Content-Disposition",
                "attachment; filename=" + URLEncoder.encode(APK_NAME, StandardCharsets.UTF_8));
        // 换 APK 后立即生效，禁止任何缓存
        response.setHeader("Cache-Control", "no-cache, no-store, must-revalidate");
        response.setHeader("Pragma", "no-cache");
        response.setHeader("Expires", "0");
        response.setHeader("Last-Modified", String.valueOf(file.lastModified()));

        // 只探大小不下载（前端可先 HEAD 拿体积）
        if ("HEAD".equalsIgnoreCase(request.getMethod())) return;

        InputStream in = null;
        OutputStream out = null;
        try {
            in = new BufferedInputStream(new FileInputStream(file));
            out = new BufferedOutputStream(response.getOutputStream());
            byte[] buf = new byte[8192];
            int n;
            while ((n = in.read(buf)) > 0) out.write(buf, 0, n);
            out.flush();
        } catch (Exception e) {
            log.error("[appUpdate] 下载失败", e);
        } finally {
            closeQuietly(in);
            closeQuietly(out);
        }
    }

    /** 定位 APK：配置优先，其次 jar 同目录，最后 user.dir 兜底 */
    private File resolveApkFile() {
        String dir;
        if (StringUtils.hasText(apkDirConfig)) {
            dir = apkDirConfig.trim();
        } else {
            dir = jarDir();
        }
        return new File(dir, APK_NAME);
    }

    /**
     * jar 运行时 → jar 所在目录；
     * IDE 直接跑 → 项目 target 目录（开发时把 apk 放 target 下即可调试）。
     * ApplicationHome 是 Spring Boot 自带类，比 System.getProperty("user.dir") 可靠：
     * user.dir 取的是"执行 java 命令时的工作目录"，从别的路径启动 jar 时会取错。
     */
    private String jarDir() {
        try {
            return new ApplicationHome(PdaAppUpdateController.class).getDir().getAbsolutePath();
        } catch (Throwable t) {
            log.warn("[appUpdate] ApplicationHome 定位失败，回退 user.dir", t);
            return System.getProperty("user.dir");
        }
    }

    private void writeJson(HttpServletResponse response, int status, String msg) {
        try {
            response.reset();
            response.setStatus(status);
            response.setContentType("application/json;charset=UTF-8");
            response.getWriter().write("{\"success\":false,\"message\":\"" + msg + "\",\"code\":" + status + "}");
        } catch (IOException ignored) { }
    }

    private void closeQuietly(Closeable c) {
        if (c != null) { try { c.close(); } catch (IOException ignored) { } }
    }
}
```

> 用 `ApplicationHome(PdaAppUpdateController.class)` 而不是启动类，避免 `mes-core-pda` 反向依赖 `mes-admin`。

## 四、前端实现

### 4.1 新增 `utils/appUpdate.js`

```js
// utils/appUpdate.js
// 从后端下载 snApp.apk 并安装。不做版本比较，固定装服务器上的那个文件。

const APK_NAME = 'snApp.apk'

// 与 utils/request.js 保持一致的基址拼法
function buildUrl() {
  const host = uni.getStorageSync('pdaHost')
  const port = uni.getStorageSync('pdaPort')
  if (!host || !port) throw new Error('未配置服务器地址，请先在登录页设置')
  // 加时间戳，防止中间层缓存住旧包
  return `http://${host}:${port}/imes/api/pda/app/downloadSnApp?t=${Date.now()}`
}

function fmtSize(bytes) {
  if (!bytes) return ''
  const mb = bytes / 1024 / 1024
  return mb >= 1 ? mb.toFixed(1) + ' MB' : Math.round(bytes / 1024) + ' KB'
}

// 下载到本地应用私有目录（Android 10+ 分区存储下依然可写，无需额外权限）
export function downloadApk(onProgress) {
  return new Promise((resolve, reject) => {
    const dir = plus.io.convertLocalFileSystemURL('_downloads/')
    const filePath = dir + APK_NAME
    // 覆盖旧包：先删，避免文件名冲突导致写入失败
    try { plus.io.resolveLocalFileSystemURL(filePath, (e) => e.remove()) } catch (e) {}

    const task = uni.downloadFile({
      url: buildUrl(),
      filePath,
      timeout: 180000,
      success: (res) => {
        if (res.statusCode === 200) {
          resolve(res.filePath || res.tempFilePath)
        } else if (res.statusCode === 404) {
          reject(new Error('服务器上未找到 snApp.apk，请联系管理员上传'))
        } else {
          reject(new Error('下载失败（HTTP ' + res.statusCode + '）'))
        }
      },
      fail: (err) => reject(new Error(err.errMsg || '下载失败'))
    })

    // onProgressUpdate 触发极频繁，必须节流后再驱动 UI，否则界面卡死
    let last = 0
    task.onProgressUpdate((r) => {
      const now = Date.now()
      if (now - last < 200 && r.progress < 100) return
      last = now
      onProgress && onProgress({
        progress: r.progress,
        text: fmtSize(r.totalBytesWritten) + ' / ' + fmtSize(r.totalBytesExpectedToWrite)
      })
    })
  })
}

// Android 8.0(API 26)+ 需要"允许安装未知应用"，且该权限无法用运行时弹窗申请
export function canRequestInstall() {
  // #ifdef APP-PLUS
  try {
    if (uni.getSystemInfoSync().platform !== 'android') return true
    const main = plus.android.runtimeMainActivity()
    const Build = plus.android.importClass('android.os.Build')
    // 反射下 SDK_INT 是直接字段，不能写成 SDK_INT()
    if (Build.VERSION.SDK_INT < 26) return true
    const pm = main.getPackageManager()
    plus.android.importClass(pm)
    return pm.canRequestPackageInstalls()
  } catch (e) {
    console.warn('[appUpdate] 权限检查失败，按已授权处理', e)
    return true
  }
  // #endif
  return true
}

export function openInstallSetting() {
  // #ifdef APP-PLUS
  try {
    const Intent = plus.android.importClass('android.content.Intent')
    const Settings = plus.android.importClass('android.provider.Settings')
    const Uri = plus.android.importClass('android.net.Uri')
    const main = plus.android.runtimeMainActivity()
    const intent = new Intent(Settings.ACTION_MANAGE_UNKNOWN_APP_SOURCES)
    intent.setData(Uri.parse('package:' + main.getPackageName()))
    main.startActivityForResult(intent, 1001)
  } catch (e) { console.warn('[appUpdate] 跳转设置页失败', e) }
  // #endif
}

export function installApk(filePath) {
  return new Promise((resolve, reject) => {
    // force: true —— 不校验版本号，直接覆盖安装（用户选定的"直接重新安装"方案）
    plus.runtime.install(filePath, { force: true }, () => resolve(),
      (err) => reject(new Error((err && err.message) || '安装失败')))
  })
}
```

**脚本**（最终实现：进度用 `uni.showLoading` + 百分比，不需要额外 data 和遮罩 UI）：

```js
import { downloadApk, canRequestInstall, openInstallSetting, installApk } from '@/utils/appUpdate.js'

handleUpdateApp() {
  // #ifndef APP-PLUS
  uni.showToast({ title: '仅 App 端支持更新', icon: 'none' }); return
  // #endif
  uni.showModal({
    title: '更新应用',
    content: '将从服务器下载 snApp.apk 并安装，是否继续？',
    success: (r) => { if (r.confirm) this.doUpdateApp() }
  })
},

async doUpdateApp() {
  try {
    uni.showLoading({ title: '准备下载...', mask: true })
    const file = await downloadApk((p) => {
      uni.showLoading({ title: '下载中 ' + p.progress + '%', mask: true })
    })
    uni.hideLoading()

    // Android 8+ 未授权「安装未知应用」时引导去设置页
    //（该权限是特殊权限，运行时弹窗申请无效）
    if (!canRequestInstall()) {
      uni.showModal({
        title: '需要授权',
        content: '请先允许「安装未知应用」权限，然后重新点击更新。',
        confirmText: '去设置',
        success: (r) => { if (r.confirm) openInstallSetting() }
      })
      return
    }
    await installApk(file)
  } catch (e) {
    uni.hideLoading()
    uni.showModal({ title: '更新失败', content: (e && e.message) || String(e), showCancel: false })
  }
}
```

## 五、⚠️ 三个必须知道的硬约束

### 1. 已不需要手动递增 `versionCode`（改用 force 覆盖安装）

安装用的是 `plus.runtime.install(filePath, { force: true })` —— **force 表示不校验版本号、直接覆盖安装**。
所以服务器上的 `snApp.apk` 是什么版本就装什么版本，**versionCode 保持 `100` 不动即可**，换包不必改 manifest，同版本重装修复也走得通。

仍需留意两点：

1. **签名必须一致**。签名不同的 APK 无论 force 与否都装不上（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`），
   必须用同一个 keystore 打包（本项目 keystore 在 `doc/` 目录）。
2. 若将来要**禁止降级**（不允许装比当前更旧的包），把 `force` 改回 `false`；那时就必须严格递增 versionCode。
3. 建议仍把 versionName 递增（3.5.5 → 3.5.6 …），便于在「我的 → 当前版本」上肉眼分辨装的是哪一版。

### 2. Android 8+ 的安装权限只能跳设置页

`REQUEST_INSTALL_PACKAGES` 是特殊权限，**运行时弹窗申请无效**，必须引导用户到
`设置 → 应用 → 此应用 → 允许安装未知应用` 手动开。首次在新机器上使用必然要走这一步，UI 已按此设计。

### 3. 替换 APK 时别让文件被占用

- **Linux 部署**：直接覆盖替换即可，正在读文件的请求不受影响。
- **Windows 上调试**：若 APK 正被读取，覆盖会提示"文件被占用"，用 `mv` 覆盖或停服务再换。
- 接口每次请求都重新读文件，**换完立即生效，无需重启服务** ✅（这正是你要的效果）。

1. 后端重新打包部署一次 —— **之后换 APK 就不用再打包了**
2. 把 `snApp.apk` 放到服务器上 `iwms.jar` 的同级目录
3. 浏览器访问 `http://{host}:8082/imes/api/pda/app/downloadSnApp` 验证能下载
   - 404 就看后端控制台日志里打印的绝对路径，确认 APK 放对位置没有
4. App 打包新 APK（**签名必须与线上一致**），放进服务器目录
5. PDA 上「我的 → 更新应用」验证：下载进度 → 系统安装界面
   - 首次在新机器上会提示去开「安装未知应用」权限，授权后**再点一次**更新
