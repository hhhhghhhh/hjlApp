## IB-PTM7330 调试（续）

### 问题 1：LPAPI 崩溃 "Cannot read property 'bind' of undefined"
- 根因：`utils/lpapi-uniplugin.js` 占位用 Proxy，导致 `require('../lpapi-uniplugin.js').default`
  也解析成 Proxy 对 `default` 属性返回的**函数**，`lpapiAdapter.js` 里 `mod.default || mod`
  拿到这个"函数"而非 Proxy，于是 `lpapi.openPrinter` 变成 undefined，再 `.bind` 报错。
- 修复：占位改为**普通对象**，列出已知方法（openPrinter/startJob/drawText/...），每个方法直接
  抛清晰安装指引错误；`placeholder.default = placeholder`。LPAPI 在标准基座下会明确提示
  "基座不含 DothanTech-LPAPI，需安装原生插件 + 自定义基座"，不再崩溃。

### 问题 2：PDF 位图渲染卡死（"位图渲染中"）
- 根因：`readBitmapPixels` 逐像素 `Bitmap.getPixel` 跨 JSBridge，591×354@300dpi≈21万次，
  约 1.4ms/像素 → 整张约 5 分钟，体验即卡死。
- 修复：`utils/adapters/ibptm7330Adapter.js` 新增 `readBitmapPixelsFast`：
  `copyPixelsToBuffer` 一次取全部像素 → `android.util.Base64.encodeToString(buf.array(), 2)`
  → JS 用 atob 解码成 Uint8Array → 纯 JS 二值化（ARGB_8888 字节序 R,G,B,A，alpha>127 且 R<128 判黑）。
  零 JSBridge 循环，毫秒级完成。任何一步失败自动回退 `readBitmapPixelsSlow`（逐像素，慢但可用）。
- 注意：之前 copyPixelsToBuffer+Base64 报 null 是因为用了 direct buffer 的 array() 为空；
  这次改用 `ByteBuffer.allocate`(堆缓冲) 保证 array() 非空。

### 2. 看 CSPrintService 源码发现并修复的 4 个 detail 字段映射 bug
对照 `LabModels.cs` / `PdaTemplateMapper.cs` / `LabEnums.cs`：

- **non-printable 未跳过**：`LabObject.printable===false` 的对象必须跳过（MapShape 前 line 49-53）。已加跳过+告警。
- **computed 变量判定过窄**：应排除所有非 Free(5)/Form(6) 的变量（Counter/1、TableLookup/2、Date/3、Formula/4、DataBase/7），原只判 1/4。改用 `isUserInput = ds===5||ds===6`，其余进 computed（与 LabEnums.IsUserInput 一致）。
- **QR 放大倍率硬编码 5**：改为按 `moduleXMm` 用默认 dpi(203) 折算 `round(moduleXMm*203/25.4)`（MapBarcode 同公式），0.51mm→4。
- 附加：`RoundRect`(type 9) → 按普通矩形输出（带告警，对照 case 9）。

### 3. pako ESM 导入 gotcha（重要，已修复）
- 项目装 pako **3.0.1**，纯 ESM 只导出命名成员（ungzip/inflate/…），**无 default 导出**。原 `import pako from 'pako'` + `pako.ungzip` 在任意 ESM 构建下 pako=undefined → 离线码解码 `pako.ungzip` 运行时报错。
- 改为 `import * as pako from 'pako'`（命名空间导入），`pako.ungzip` 在 Node ESM / Vite / webpack 下均可用。

### 4. 打印静默失败修复（上轮落地，本轮复核仍在）
- `printerManager._ensureConnected()`：原 `connect()` 返回 `{verified}` 不抛错，自动回连失败（日志 errCode 10002=打印机未连）仍继续打印 → `commitJob` 返回 statusCode:3、出纸空白。改为连完再 `adapter.isConnected()` 复检，未连上抛清晰中文错误。
- `lpapiAdapter`：新增 `throwIfPrintFailed(ret, action)`，4 个 commitJob 点（printTestLpapi/printText/_printCalibrationLabel/printTemplate）均改 `safeRet(await commitJob(...))` + 抛错（statusCode 非 0/undefined 即失败）。`safeRet` 抽成纯对象避免循环引用序列化爆栈。
- `lpapi-uniplugin`：加 `polyfillTextEncoder()`（App-plus 缺 TextEncoder 时补 UTF-8 实现），消除 SDK "TextEncoder is not defined" 告警（该告警 SDK 内部 catch 回退 encodeUtf8，本身 benign，但补垫片更稳、确保二维码/中文走标准 UTF-8）。

### DPI 修复（IB-PTM7330 用打印机 dpi 而非模板）
- 用户指出 IB-PTM7330 是 300dpi，模板 pdaTemplate 默认 203 不可信，应按打印机实际 dpi 渲染。
- 厘清 DPI 语义：LPAPI/ZPL 用模板 dpi（LPAPI 仅用于点值→mm 换算，位图分辨率由 SDK 实测定），正确不动；**IB-PTM7330 是位图机，位图分辨率必须=硬件300dpi**，原 `printTemplate` 却 `(tpl.page.dpi)||this.dpi` 误用了模板 203 → 位图算错。
- 改 `ibptm7330Adapter.js`：`printTemplate`/`printTextLines` 直接用 `this.dpi`(300)，`setLabelSize` 去掉可被外部覆盖的 dpi 参数 → 位图恒按硬件 300dpi 栅格化。模板 203 仍保留（ZPL/CPCL 点指令用），符合用户"不管他"。
- `node --check` 通过。已把该 DPI 铁律写入 MEMORY.md 的 IB-PTM7330 条目。
