## ERP 物料「旧名称」字段落地（jzckj-hjl / cc-admin-api + cc-admin-web）

> 注意：本次改动的仓库是 `D:\newxiangmu\hjl\jzckj-hjl`，**不是 hjlApp**。

### 需求
`ErpMaterialServiceImpl.syncMaterial()` 物料拉取入库要增加「旧名称」，前端列表 / 后端 / 数据库三处都要加。

### 关键实测结论（推翻了需求里给的字段名）
- 需求里给的 `FOldName` **不存在**，金蝶直接报：`元数据中标识为FOldName的字段不存在`。
- 用 `QueryBusinessInfo` 拉 `BD_Material` 全量元数据后，只有两个候选：
  - **`FOldNumber`（旧物料编码）** —— 测试账套/生产账套**都有**，且**普遍有值**（`A.BC.00001` → `A.BC.001`，抽查 22/25 非空）
  - `F_HJL_JMC`（旧名称）—— **只有生产账套有**，抽查非空率 0
- 用户拍板：ERP 取 `FOldNumber`，MES 侧命名 `oldItemName`。

### 改动清单
| 层 | 文件 | 改动 |
|---|---|---|
| DB | `hjl.t_co_item` | `ADD COLUMN old_item_name varchar(255) NULL COMMENT '旧名称' AFTER item_name`（本地 dev 库已执行） |

前端第二张表（导入预览弹窗）共用同一套 `columns`，自动带上新列。

### 验证
- `mvn -pl esb-interface,mes-core-production -am compile -DskipTests` → BUILD SUCCESS
- 字节码核对：`CoItem.class` 有 `getOldItemName()/setOldItemName()`；`ErpMaterialServiceImpl.class`、`ErpQyCoItem.class` 含 `FOldNumber`；`CoItemController.class` 含 `oldItemName`
- 前端用 `@babel/parser` 校验 `index.vue` 通过
- `QueryGenerator.initQueryWrapper(new CoItem(), paramMap)` **不会**给 `oldItemName` 额外拼精确条件（它只读 `new CoItem()` 的属性值，全为 null），所以模糊查询按预期生效

### 待办 / 风险（重要）
1. **存量 46819 条物料不会自动回填**。同步是增量的（按 `FApproveDate >= 水位`，水位在 `t_sys_parameter_table.syncMaterial`，本次查到是 `2026-09-16 14:05:17`）。要回填必须把水位改早、触发一次全量重拉：
   `UPDATE t_sys_parameter_table SET param_value='2000-01-01 00:00:00' WHERE param_name='syncMaterial';`
2. **生产库 DDL 需手工执行**（本次只改了本地 dev 库 `hjl`）：
   `ALTER TABLE t_co_item ADD COLUMN old_item_name varchar(255) NULL COMMENT '旧名称' AFTER item_name;`
3. **前端看不到新列时**：该页表格有 localStorage 列配置（`table_state_*`），`loadTableState()` 会用存档里的 `visibleColumns` 覆盖 `group` → 新列默认隐藏。右键表头 →「显示全部列」或「重置配置」。
4. ERP 里 `FOldNumber` 的中文名是「**旧物料编码**」，取值形态是编码；MES 界面标签按用户要求用了「旧名称」。若觉得别扭，改一处 label 即可。

## 补测（同日 16:50）：旧名称字段写法 + 多账套全量核对

用户再次追问「旧名称」：`FOldNumber.Fname` / `FOldNumber_Fname` / `FOldName` 到底有没有。三套账逐个实测：

| 字段写法 | 测试账套 demo1<br>(鸿嘉丽测试0715) | 生产账套 Administrator<br>(深圳市鸿嘉利新能源有限公司) | 设备制造项目管理<br>(110.41.170.79) |
|---|---|---|---|
| `FOldNumber` | ✅ 有 | ✅ 有 | ✅ 有 |
| `FOldName` | ❌ 不存在 | ❌ 不存在 | ❌ 不存在 |
| `FOldNumber.FName` / `.Fname` | ❌ | ❌ | ❌ |
| `FOldNumber_FName` / `_Fname` | ❌ | ❌ | ❌ |
| `F_HJL_JMC`（中文名就叫"旧名称"） | ❌ 不存在 | ✅ 有 | ❌ 不存在 |

**取值实测（全表拉取，TopRowCount=0/Limit=0）**
- `FOldNumber`：测试账套 46828/46828 = **100% 非空**；生产账套 48099/48099 = **100% 非空**。
  与 `FNumber` 对照：**97.8% 不同**（`A.BC.00001` → `A.BC.001`，是"旧编码"体系，不是 FNumber 的复制），2.2% 相同。
- `F_HJL_JMC`：生产账套 48099 行里只有 **150 行有值（0.3%）**，值为中文品名（如"320KW双枪直流充电桩"）。
  第三账套 `FOldNumber` 虽有值但全是**空格字符串 `" "`**，等价于空。

**新增两条硬结论（已写进技能）**
1. `ExecuteBillQuery` 成功时顶层**直接是裸二维数组**，没有 `{"Result":...}` 外壳；失败才是
   `[[{"Result":{"ResponseStatus":{"Errors":[{"Message":"..."}]}}}]]`。对结果直接 `.get('Result')` 会抛
   `AttributeError: 'list' object has no attribute 'get'`（本次连踩两次）。
2. `FOldNumber.FName` 这类点号写法金蝶不认，报错是 `元数据中标识为FOldNumber的字段不存在`
   ——**报错指向前半段，极具误导性**，实际是整串被当成一个字段标识。
3. `101.37.150.76:8898` 是 nginx 静态站（任何请求都 405），**WebAPI 在 `8899/k3cloud`**；
   `110.41.170.79/k3cloud` 是另一套独立账套（`momtest` / DBid `67adf90470af84`）。

**风险提醒**：`F_HJL_JMC` 只在生产账套存在 → **绝不能写死进 FieldKeys**，否则测试账套物料同步整条 500。
当前代码取 `FOldNumber`（三套账都在）是安全选择。若确实要用"旧名称"文本，须做「探测 + 条件拼接」。
