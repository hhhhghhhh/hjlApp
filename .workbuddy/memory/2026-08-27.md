## LPAPI 打印"完全不清晰"根因 + 修复
- 现象：PTM230X 对齐修好后能印出，但文字/条码发虚、灰蒙蒙（"完全不清晰"）。
- 排查（看控制台日志 + 反编译 dothan-lpapi-ble/index.js）：
  - 位图分辨率正确：startPage 报 width:576 height:177 printerDPI:300（@300dpi 原生，无缩放模糊）。
  - `printDarkness:10` 在该 SDK 是 1~15 档（High=10），合理；`printSpeed:3` 合理；`threshold` 未设→SDK 默认 150，合理。
  - **真正根因**：SDK 的 `imageProcess({colorMode})` 在 `colorMode` 未设置(0)时走 `void 0` 分支，**把 canvas 抗锯齿灰阶像素原样下发打印机** → 灰蒙蒙/发虚。
    - colorMode: 1=GRAY, 2=BLACK_WHITE(二值化), 3=HALFTONE, 0/undefined=发灰阶。
- 修复（utils/adapters/lpapiAdapter.js）：
  - `_startJob` 的 `startJob(...)` 增加 `colorMode: 2`；
  - `buildCommitOpts` 增加 `colorMode: 2` + 显式 `threshold: 150`（双重保险，覆盖模板打印/测试页/校准/文本全部入口）。
- 验证：`node --check` 通过。待用户真机重打确认文字变锐利（控制台 commitJob options 里应出现 `colorMode:2,threshold:150`）。
- 结论：LPAPI 凡用 canvas 绘制，必须显式 colorMode:2，否则必发虚。

## itemLotSn 打印"混乱看不清"根因 + 修复（同一天续）
- 现象：PTM230X 上 itemLotSn 文字一团混乱、看不清；调到字号 4/8 都更糊；itemName（18mm 宽）尚可辨认。
- **关键认知（翻 SDK 源码确认）**：dothan-lpapi-ble 整个文件 `wordWrap` 出现 **0 次**——模板里的 `wordWrap:true` 是**被忽略的无效字段**。文本换行靠 SDK 的 `autoReturn`（默认 `d.Char` 按字符换行）+ `autoShrink`（默认开启）组合。
- 根因：itemLotSn 文本框 **9mm 宽 × 2.41mm 高、7pt**。7pt 行高≈2.9mm > 框高 2.41mm（连一行都装不下）。长流水号在 9mm 内折成多行 → 多行总高远超 2.41mm → `autoShrink` 默认开启把整段压成"芝麻字"塞进小框 → 打印混乱。字号越大行数越多、压得越糊（所以 4/8 都不清）。itemName 框宽 18mm 且内容短、基本单行，autoShrink 只轻微压一下 → 尚可辨认。
- 修复（utils/lpapiTemplate.js `renderText`）：多行文本时**关闭 autoShrink** 并按实际换行行数（`lpapi.splitText` 获取，失败回退估算）**把框高撑到容纳所有行**；单行时保留原 autoShrink 行为（不影响其他模板）。`node --check` 通过。
- **重要限制**：App 这道保险只防止"被压成芝麻字"。当前模板 itemLotSn 框太小（2.41mm 高），撑高后会与 QR/下文字重叠 → **必须同步在 CodeSoft 把 itemLotSn 框加宽加高、重排布局**（见下）。20×15mm 同时放 QR+itemLotSn+itemName 很挤，建议：QR 9×9 居中靠上(y1~10)、itemLotSn 整宽 18mm 放在 y10.5 高约 4mm；itemName 若内容不长可保留，否则建议删除（QR 已含该信息）。
- 结论：LPAPI 文本"宽度不够"的真正坑是 **autoShrink 默认开 + 框高不足**，不是缺自动换行。

## 新增：LPAPI 垂直方向偏移（与水平对称）
- 需求：用户要求"再加个垂直方向偏移"。水平已有（全局 `lpapi_offset_delta` + 模板级 `page.offsetXMm`），垂直做对称实现。
- 语义：垂直方向**无打印机对齐基线**（标签垂直起点由纸张类型定），故垂直偏移是**纯手动 delta**：
  - 全局 `lpapi_offset_delta_y`（storage），正=下移(y 增大)、负=上移；落点由标签默认贴顶(0)叠加。
  - 模板级 `page.offsetYMm`，优先级高于全局（个别模板特调）。
- 改动：
  - `utils/adapters/lpapiAdapter.js`：新增 `OFFSET_DELTA_Y_KEY='lpapi_offset_delta_y'`、`loadOffsetDeltaY()`、`computeOffsetY(tpl)`（优先 tpl.page.offsetYMm 否则 loadOffsetDeltaY）；`printTemplate` 算 `offsetY=computeOffsetY(tpl)` 并传给渲染器 `renderTemplateToLpapi(..., {offsetXMm, offsetYMm})`；`printTestLpapi`/`printText` 用 `offsetY=loadOffsetDeltaY()` 并把每个 draw 的 `y` 改为 `y+offsetY`（测试页/文本无模板，用全局值）。
  - `utils/lpapiTemplate.js`：`renderTemplateToLpapi` 增 `opts.offsetYMm`，透传给 `renderOne` 及 5 个 render 函数；各 draw 的 `y` 改为 `y+oy`，**返回值仍用原始 y**（与水平一致，越界检测继续按标签坐标系、不被偏移污染）。
  - `utils/printerManager.js`：新增 `getOffsetDeltaY()`/`setOffsetDeltaY(v)`（存 `lpapi_offset_delta_y`）。
  - `pages/print/printSetting.vue`：data 加 `offsetDeltaY`，`syncConnection`/`onShow` 读 `printer.getOffsetDeltaY()`；LPAPI 区块加"垂直偏移微调(mm)"输入框(placeholder "0=不微调") + 提示"偏下填负值/偏上填正值"；新增 `saveOffsetDeltaY()`。
  - `pages/print/labelTemplate.vue`：水平偏移输入框下方加"垂直偏移微调(mm)"输入框，绑定 `tpl.page.offsetYMm`（模板级，提示个别模板特调）。
- 验证：5 个文件 `node --check` 通过。需在 HBuilder 重运行到手机生效。
- 与水平关系：水平 delta 叠加在 printerAlignment 自动基线(右/中/左)之上；垂直 delta 直接叠加在贴顶(0)之上。两者独立、互不影响。
