## LPAPI 文本"字高改小没反应"根因 + 修复（框高驱动字号）
- **根因（已用 LPAPI SDK 源码坐实）**：`drawText` 的 `R = fontHeight || height || 默认字号`；仅当"字实际高 > 框高(C) 且 autoShrink 开启 且 R≥min(6)"才把 R 往框高压缩。本机文本框高恒为 1.02mm（导入的 heightMm），用户改 fontHeight 到 1/0.5 都 ≤ 框高 → 走"对齐分支"、不收缩；而原生 LPAPI 在**给定 height** 时把 ≤框高的字号统一适配进该框 → 1 与 0.5 打印一样大。readme 明确：`height:0` = "以实际字号高度显示/不限制"。
- **编辑器缺陷**：文本属性面板（`pages/print/labelTemplate.vue` 的 `v-if="el.type==='text'"` 模板）原本**没有框高输入**（框宽/框高输入框属于 box/line/image 模板），所以用户"只能调字高、不能调框高"。
- **修复（用户指定"填框高字体自适应"）**：
  1. `utils/lpapiTemplate.js` `renderText`：单行文本改为"**框高存在即字体自适应填满框**"——`frameH>0` 时 `autoShrink=true & constrainHeight=true`，`height` 传 `frameH`；`frameH=0` 时 `height:0 + autoHeight:true`（字号严格按 fontHeight）。多行仍 `constrainHeight=false`（不收缩、按内容撑高）。`fitToFrame` 字段不再参与决策。
  2. 编辑器文本面板新增"框高 (mm)"输入，绑定 `el.height`（`type="digit"`，无 min），使框高成为可调的字号旋钮。
- **验证**：`node --check` 通过；分支逻辑确认 框高 0.5/1.0/1.82 → drawH 同值且 autoShrink=true，0 → drawH=0+autoHeight，多行 → drawH=0+autoShrink=false。QR 自适应路径未动。
- **使用方式**：现在改文本大小请调"框高"；"字高"仅在框高留空时作为严格字号生效。

## 修正：框高"往大调可以、往小调不行"（autoShrink 下限/只缩不放）
- 上一版 `frameH>0 → autoShrink=true` 仍不行：用户实测往大调字号变大、往小调不变。
- **根因（已抠 LPAPI SDK 收缩分支）**：`drawText` 的 `autoShrink` 仅在"字实际高>框高(C) 且 R≥minFontHeight(n)"时把字号 ×0.95 递归下压；H5 默认 `n=minFontHeight||6`（≈6px≈0.5mm）是**最小字号地板**，且无向上放大分支。原生 SDK 实测"可向框高放大、缩小到地板即停" → 表现就是"往大可以、往小不行"。
- **修法（绕开 SDK 缩放）**：单行 `frameH>0` 时不再依赖 autoShrink，而是 `fontHmm = frameH`（直接把字号算成框高）、`autoShrink=false`、`constrainHeight=false`（`height:0`+`autoHeight:true`）。字号严格=框高，双向可控，仅打印机硬件最小字号不可破。`fontHmm` 由 `const` 改 `let` 以支持本分支覆写。
- **验证**：`node --check` 通过；分支确认 框高 0.5/0.8/1.0/1.5/2.0/3.0 → 最终 fontHeight 精确=框高；框高=0 → 退回字高严格(1.06)；多行 → fontHeight 不变。QR 路径未动。

## 再诊：框高字高字宽都填 0.5 仍不缩小 —— 非模板问题
- 用户把 keySn 的 框高/字高/字宽 全填 0.5，打印仍不缩小，怀疑是模板原因。
- **代码路径已坐实正确**：`num("0.5")=0.5` 正常传入；`renderText` 在 `frameH>0` 时 `fontHmm=0.5`、`autoShrink=false`、`height:0`；LPAPI JS SDK 内部 `height<=0` 走 `measureTextExt(t)` 按 `fontHeight` 实测 → 0.5mm 在 H5 下**会被尊重**（H5 不钳制）。readme 确认 `height:0`=以实际字号高度显示、`fontHeight` 单位 mm。
- **结论**：0.5 不缩小 = **真机原生 LPAPI 打印引擎的最小字号下限**（0.5mm@300dpi≈5.9px，低于引擎地板 ~0.6–0.7mm/~7px 被钳住）。这正好解释上一轮"往大调可以、往小调不行"。属**硬件/驱动下限，不是模板问题，覆盖模板也救不了**；内置模板框高(1.02/1.82)均高于下限、打印正常。
- **若 H5 预览也压不缩** → 不是下限，是**旧构建未生效**（没硬刷/打包的是改前代码）；需 `Ctrl/Cmd+F5` 硬刷或重打包。
- **验证法**：keySn 框高 2.0 vs 1.0 vs 0.8 vs 0.5 各打一张；能区分的就是下限临界（约 0.8mm）。

## 文本"调小不行"真因 = SDK 默认最小字号地板(2mm) + 改为"只填一个高度"
- **真因（抠 LPAPI SDK 源码坐实）**：`js_sdk/index.js` 的 `drawText` 有 `t.fontHeight < e && (t.fontHeight = e)`，`e = getMineFontHeight(t) = xe.FONT_SIZE_MIN_DEFAULT`，而 `xe.FONT_SIZE_MIN_DEFAULT = 2`（**2mm 默认最小字号地板**）。我们此前没传 `minFontHeight`，于是任何 <2mm 的字号被强制拉到 2mm → 用户调 0.5/0.6/0.8/1.0 全一样大、调 2/3 才变（即"调大可以、调小不行"）。这不是硬件下限，是 SDK 默认下限。
- **修复**：`utils/lpapiTemplate.js` `renderText` 的 drawText opts 增加 `minFontHeight: 0.1`（压低地板到 0.1mm≈1.2px@300dpi）。node 复刻钳制逻辑验证：旧(不设) 0.5/0.6/0.8/1.0→全钳 2；新(设0.1) 0.5/0.6/0.8/1.0/2/3 全部如实渲染。
- **用户新需求：只填一个高度，字体大小和换行自适应**。落地：
  1. `renderText`：`fontHmm = frameH>0 ? frameH : num(el.fontH,3)` —— **框高即字号**（单行/多行统一以框高作为行高）；`autoShrink` 始终关闭（绕开 SDK 只缩不放+地板缺陷）；多行时框高放不下全部行则把绘制框撑高（绝不压扁）；`height:0 + autoHeight` 让 SDK 按实际字号高度显示。
  2. 编辑器文本面板（`pages/print/labelTemplate.vue`）精简为"只填一个高度"：删除 **字高**、**字宽** 输入，删除 **适应框高** 开关；新增提示"框高即字体大小（只填这一个高度）；文本按框宽自动换行"。字体大小随框高变、换行按框宽自动。
  3. **修正（关键）**：上一版把"框高"输入依赖通用 `showFrame(el)` 块，但 `showFrame` 对 `anchor==='topLeft'` 元素返回 false —— 而 CodeSoft 导出的文本全是 TopLeft 基点 → **框高输入框根本不显示**，用户改不了 `el.height`。已把"框宽 + 框高/字号"两个输入直接钉进文本块（`<template v-if="el.type==='text'">` 内，不依赖 showFrame，始终可见），并改 `showFrame` 返回 `el.type==='qrcode' || 'barcode'`（不再含 text），避免居中文本重复显示。
- **验证**：`lpapiTemplate.js` `node --check` LP_SYNTAX_OK；SDK 钳制复刻验证通过。注意：框宽(框宽=换行列宽)仍保留可调，它不是"高度"，符合"只填一个高度"。
