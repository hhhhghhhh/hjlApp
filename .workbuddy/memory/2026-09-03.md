- ⚠️ 这是编译输出目录，**`mvn clean` 会整个删掉** → 建议开发环境配 `cc.admin.path.apk: D://opt//apk`，生产留空（jar 同目录）。

### 2. web 端跳 403 的真因（重要教训）
- 现象：后端日志显示 HEAD 请求**成功**（读到 15.8MB），但 web 点按钮仍跳 `http://localhost:8082/imes/403.html`，且 Controller **没有第二次日志**（说明浏览器那次 GET 根本没到 Controller）。
- **根因**：`<a href>` 的浏览器原生导航**不带 Authorization / Tenantid header**；而 axios 请求由 `boot/api/index.js` 自动带上。后端 `TenantRequestHandler`（日志：`获取到的租户ID为:xxx`）**依赖这些 header**，缺了就 403 —— **即便 Shiro 已对该 URL 配了 anon**。
- 附带现象：axios 默认**跟随 302**，Shiro 的 `CommonController.noauth` 重定向到 `/imes/403.html`，跟随后用原 origin 变成 `localhost:8082/...`，所以地址栏跳到了后端域名。
- **修复**：下载改为 **axios + `responseType: 'blob'`**，用 `URL.createObjectURL` 生成链接再触发 `<a download>`，从而复用统一请求头。同时删掉了 HEAD 预检（GET 本身就能判定成败）。

### 3. 最终代码要点（cc-admin-web/src/layouts/index.vue 的 downloadApp）
```js
const res = await this.$axios.get(path, { responseType: "blob" });
if (res.data?.type?.indexOf("json") >= 0) throw new Error("server-error"); // 后端出错返回 JSON 而非 apk
const url = URL.createObjectURL(res.data);
// ... a.click() ...
setTimeout(() => URL.revokeObjectURL(url), 10000); // ⚠️ 立即 revoke 会让部分浏览器中断大文件下载
```

### 4. 项目事实
- `quasar.conf.js` 里 **eslint-loader 是注释掉的**（第 68 行），lint 错误**不会阻断构建**。
- eslint `index.vue` 有 5 个既有空白风格错误（8/13/53 行含空格空行、文件末尾缺换行），与本次改动无关，未擅自修改。

### 5. ⚠️ 更正：上面第 2/3 节的 axios blob 方案**已被推翻**
- 按 axios 方案改完后，后端日志显示 **200 OK + Content-Disposition: attachment**（请求成功），但 UI 仍弹"下载失败"。
- **真因在 `boot/api/index.js:155` 的响应拦截器 `(r) => r.data`** —— 它把 `r.data` 本身作为响应返回，所以 `await this.$axios.get(...)` 拿到的**就是 data**，`res.data` 是 `undefined`；且拦截器还会给 Blob 强行加 `headers` 字段（Blob 是 frozen，赋值失败/进 catch 后包装成普通对象）。`URL.createObjectURL(undefined)` 直接抛错 → catch。
- **最终改为原生 `fetch`**（绕开项目 axios），自己塞 header（注意租户头是**小写 `tenantId`**，与拦截器一致）：
```js
const headers = {};
if (localStorage.Authorization) headers.Authorization = localStorage.Authorization;
if (localStorage.tenantId) headers.tenantId = localStorage.tenantId;
const resp = await fetch(process.env.BASE_URL + path, { headers });
if (!resp.ok) throw new Error("HTTP " + resp.status);
const blob = await resp.blob();
if (blob.type && blob.type.indexOf("json") >= 0) throw new Error("server-error");
const url = URL.createObjectURL(blob);
// ... a.click() ...
setTimeout(() => URL.revokeObjectURL(url), 10000);
```
- 对比项目既有写法 `printButton.vue:777 downloadFile`（`this.$axios({responseType:'blob'}).then((res) => new Blob([res], {type}))`）：它们直接用 `res`（而非 `res.data`），正是绕开了这个坑；但它们**立即 revokeObjectURL**，对 15.8MB 的 APK 有中断风险，故保留延迟释放。

## PDA 端「WGT/WGTU 文件格式错误」排查与修复（2026-09-04）

### 1. 先验证服务器文件（结论：文件没问题）
node 校验 `mes-core-pda\target\classes\snApp.apk`：大小 15794864、`50 4B 03 04` ZIP 魔数、含 `AndroidManifest.xml`/`classes.dex`/`META-INF`/`resources.arsc` → **真 APK**。（内含 `manifest.json` 是 uni-app 应用配置，非 WGT 特征。）

### 2. 四处修复（均在 `utils/appUpdate.js`）
1. **`_downloads/` → `_doc/`**：公共下载目录在 Android 10+ 分区存储下写入不可靠，`plus.runtime.install` 拿不到文件会报「APK文件不存在 / WGT文件格式错误」。
2. **删除竞态（真凶，第 2 次更新必现）**：`plus.io.resolveLocalFileSystemURL` / `entry.remove` 都是异步，初版"发起删除后立刻下载"导致删除回调姗姗来迟把新下载的文件删掉。改为 `removeOldApk()` Promise 化 + `await` 后再下载。
3. **并发锁**：模块级 `_downloading`，连点时第二次 reject「正在下载中，请稍候」。
4. 另加 `verifyApkFile()`：校验文件存在、大小 ≥1MB、路径以 `.apk` 结尾（否则 `entry.copyTo(_doc,'snApp.apk')` 改名）。

### 3. node 模拟对照验证（关键证据）
mock `plus.io` / `uni.downloadFile` 跑两次更新：
- 修复前：第1次成功；第2次时序 `downloadFile开始 → remove开始 → downloadFile完成 → remove完成`，**结果 ❌ APK文件不存在 → WGT/WGTU文件格式错误**。
- 修复后：第2次时序 `remove开始 → remove完成 → downloadFile开始 → downloadFile完成`，**结果 ✅ 安装成功**。
- 与用户 PDA 现象（首次能装、后续报 WGT 错误）吻合。

### 4. 官方资料要点
- 「不加 `force:true` 时系统默认把包识别为 WGT 热更包」→ **`force:true` 必须保留**。
- `plus.runtime.install` **按扩展名判断 APK/WGT**；`uni.downloadFile` 回落的 `tempFilePath` 通常无 `.apk` 后缀，必须改名后才能 install。
